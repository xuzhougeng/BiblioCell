01 定位与收录范围

这个库首先服务个人查找、阅读和复用植物单细胞研究。文献是否已经收录，与全文、数据编号和样本信息整理到了什么程度，是两个独立的问题。合格文献即使没有 PDF、没有公开原始文件，也应留下记录和待补状态。

先覆盖

文献目录

收集题目、标识符、摘要、来源和基本标签；可以在信息不完整时入库。

再连接

数据来源

确认论文产生或复用的数据，记录 accession、文件入口与可用性。

按需深入

可复用资源

补齐全文、补充材料、样本关系、矩阵和细胞注释，支持后续分析。

核心目录纳入实际产生或实质性分析植物单细胞、单核测序数据的原创研究和方法研究。scRNA-seq、snRNA-seq 优先完善；结构同时允许 scATAC-seq、单细胞多组学和长读长等类型。综述、纯空间转录组和其他相关资料可保留为参考记录，并与核心目录区分。

当前网页是设计原型。 示例记录不代表真实检索结果；新增条目与整理信息仅保存在当前浏览器。SQLite 结构已独立提供，原型尚未连接数据库，也未运行每日采集。

02 核心关系：文献、数据集、资料

文献是管理入口，数据集是独立对象，附件是可不断补充的资料。 一个数据集拥有稳定内部 ID，外部仓库编号作为关联记录保存。论文、预印本与数据集之间的关系需要明确角色和来源。

GEO 的 Series、Sample 和 DataSet 具有不同含义，GSM 可以出现在多个 GSE 中；SRA 也分别组织 Study、Sample、Experiment 和 Run。外部编号不能直接作为独立数据集或生物学重复的计数单位。[1][2]

关联角色含义计数处理
generated该文献新产生此数据集确认来源后计入独立数据集
reused该文献使用已有数据集新增文献关联，不自动新增原始数据集
reprocessed该文献重新处理已有数据记录处理关系与派生资料，保留原始来源

同一论文可以同时产生水稻根的数据、复用拟南芥根的数据。两条关联分别保存角色，数据集本身无需复制。预印本正式发表后，建立版本关系并继续指向已有数据来源。

03 数据表与核心字段

SQL 使用关系表保护身份、来源和关联的一致性。业务界面仍围绕三个对象展开，用户无需操作所有底层表。完整字段类型、约束和索引以交付的 schema.sql 为准。

按整理深度采集字段

阶段主要信息缺失时的处理
发现时题目、DOI / PMID / 预印本标识、作者、日期、摘要、来源、发现时间允许缺少 DOI、摘要或全文；至少保留能够定位来源的记录
初步整理物种、器官、组织、技术、实验处理、原始数据或复用关系保留原文，未知单独标记；可多选的维度不压成唯一值
获取资料全文、补充文件、数据页面、代码、下载地址、最近检查时间区分未检查、找不到、未公开和链接失效
准备复用样本关系、参考版本、矩阵、cell metadata、细胞注释、文件校验由研究需求驱动；样本与文库的详细模型留待后续扩展

必须保存的语义

数量的统计范围：作者报告的细胞数、下载矩阵中的 observations 数、重新过滤后的细胞数分开保存，并附来源和范围。未知不写为 0。
字段来源：关键字段可以同时保存原始表述、标准化结果、来源 URL、正文位置和审核信息。新值出现时保留冲突记录。
资源身份：同一文件的不同下载位置可以指向相同资料；链接存在不等于本地已保存，文件已保存不等于已解析。
人工修订：采集程序更新来源元数据，用户编辑整理信息。对已人工确认的科学字段，先保留新候选值，再决定采用哪一个。

04 状态独立，缺口可见

单一的“完成 / 未完成”无法表达实际进度。状态应围绕具体问题设计，而不是让缺少全文阻塞整个文献条目。

状态维度回答的问题示例
收录判断这项研究是否属于收录范围？pending / included / excluded / uncertain
全文我们找到了什么、保存了什么？not_checked / missing / linked / stored / unavailable，由资源推导
数据关联数据来源是否已经确认？not_checked / missing / linked / partial / verified，由关联推导
个人阅读我是否读过、是否需要重点跟进？unread / skimmed / read；另有优先级与收藏
已纳入全文待补数据编号已找到未读

“待补全文”“待判断”“数据待核实”等清单由记录状态自动生成。处理完一条记录后，它自然离开相应清单，避免再维护一份容易不同步的任务表。优先级可由用户决定，自动流程不强迫每一篇论文达到同样的整理深度。

stored 表示数据库记录了本地文件路径。文件是否仍然存在、能否解析、校验和是否一致，需要后续文件服务验证。当前空数据库仅验证结构约束。

05 网页信息结构

桌面界面以固定侧栏、顶部检索和主内容区组成。文献列表承担日常工作入口，详情在侧边抽屉中打开，保留当前搜索与筛选上下文。配色使用浅底、低饱和绿色和清晰的表格边界，状态通过文字与颜色共同表达。

页面主要内容常用操作
总览文献、数据集、整理缺口、最近活动进入对应列表；新增文献
文献库题目、来源、年份、物种、组织、技术与状态组合筛选、搜索、排序、查看详情、导出
数据集内部 ID、来源、物种、模态、关联文献、资源状态查看资料和来源关系；逐步核实外部编号
待补事项待判断、待补全文、数据待核实按优先级处理；直接打开原条目
更新来源来源接入状态、采集日志的位置和含义当前展示待接入状态；后续查看成功、失败和变化
数据结构主要实体、角色和设计资料查看结构说明、下载 SQL

文献详情

概览：摘要、基本元数据、物种与主题标签。

数据与附件：关联数据集、正文与补充资源、数据入口。

笔记：个人阅读、判断、优先级与研究记录。

新增文献

题目必填，其他元数据可以后补。DOI 需要规范化后检查重复；不能因为缺少 DOI 或 PDF 拒绝新增。

确认添加后立即进入列表，统计随数据更新；新增真实条目与原型示例条目保持可区分。

演示原型的筛选、详情和状态修改使用浏览器数据完成。支持当前列表 CSV 导出，以及浏览器 JSON 的导出和追加导入；导入保留已有重复记录，资料导出只包含元数据和链接。真实后端接入后，界面结构可以保留，再将原型的简化字段映射到 SQLite 的关系与状态。错误和空结果使用明确文案，不把“没有匹配结果”误显示成“数据库没有该类研究”。

06 每日发现与补全流程

每日采集由独立后台任务执行。各来源维护自己的查询版本、游标和最后成功水位。新记录、旧记录修改、预印本正式发表以及数据延后公开都需要被追踪。同步时间优先使用来源的创建、更新或索引时间；发表日期用于文献展示。[3]

① 采集并保存来源记录

先保留原始响应、来源标识、内容摘要和抓取时间。记录不完整也先存档，避免丢失发现线索。

② 识别身份与版本

先根据标准化 DOI、PMID 等确定性标识匹配。题目与作者相似只生成疑似重复提示；预印本与正式论文建立关系。

③ 判断范围并提取基本字段

规则或模型给出符合、不符合或证据不足，并保留证据。没有全文不应自动判定为不符合。

④ 追踪数据与附件

提取编号候选后向官方仓库验证；判断其是新产生、复用还是正文中的参考资料。可获取全文就补充，否则保留待补状态。

⑤ 写入变化并推进断点

整个批次成功后推进水位；失败保留已处理页和错误信息，下次补齐。同步不得覆盖用户笔记和人工确认结果。

for each enabled source:
    run = start(last_successful_checkpoint, fixed_end_time)
    for each fetched page:
        save_source_snapshots(page)
        resolve_identifiers_and_versions(page)
        screen_and_extract_with_evidence(page)
        update_automatic_fields_only(page)
        preserve_manual_edits_and_conflicts(page)
        save_page_progress(run)
    if all pages succeeded:
        commit_checkpoint(run)
    else:
        record_failure_without_skipping_unfetched_time_range(run)

可用 7–14 天重叠窗口作为起始参数，再根据观察到的延迟调整；定期比较已有社区清单和已知论文集合。覆盖率应针对有明确范围的参考集合报告，不能仅凭每日任务运行成功就声称已经找到所有研究。

每个 SQLite 连接启用 PRAGMA foreign_keys = ON。采集更新使用指定字段的 UPDATE 或 UPSERT；避免 INSERT OR REPLACE papers，其删除再插入行为可能级联删除已有个人整理。修改时显式维护 updated_at。

后端接口草案

接口职责

07 交付与下一阶段

本次提供

可执行 SQLite 结构、初始化工具和空数据库；带演示数据的网页原型；文献与数据关系、状态设计及后续接入说明。

网页能够用于检查页面布局和整理操作的使用方式。演示内容不应导入正式文献库作为事实。

后续接入

真实 SQLite 读写 API、附件文件管理、历史文献回填、文献来源增量同步、数据编号验证和后台调度。

有具体分析需求后再细化样本、捕获、文库、Run 和标准化表达对象。

下一步建议先把现有界面接到单人后端，并导入已有文献清单；随后选择一个文献来源跑通完整的同步、失败重试和人工核查链路。矩阵处理和图谱浏览可以沿已有数据集继续增加，不影响前期目录积累。

验收关注点：已知文献可检索；重复标识能被阻止；缺少全文仍可入库；一篇论文可正确关联多个新旧数据集；用户笔记不被采集覆盖；失败的同步不会跳过未抓取的时间段。
